## 当前行为

- Android「更多 → 外部浏览器 → 设置默认浏览器」调用 `superjlu://browser-settings`。卡片及原生接口已启用，桌面端卡片按 UA 保持隐藏。
- 设置对话框显示名称、图标和单选项：每次询问、跟随系统默认浏览器、具体网页应用。只有点击「保存」才更新偏好；切换单选项后取消、返回或销毁页面不保存，也不打开测试网址。
- 发现候选沿用第 23 版：普通网页、`text/html`、`application/xhtml+xml` 的有限 `<queries>` 和 `MATCH_ALL | MATCH_DEFAULT_ONLY | GET_RESOLVED_FILTER`；检查通用网络过滤器并按包去重。
- 初始为「每次询问」，系统面板使用显式组件及原地址／匹配 MIME，其他候选通过 `EXTRA_ALTERNATE_INTENTS` 提供。API 29+ 禁止单候选自动启动。第 24 版不再显示候选数量 Toast。
- 「跟随系统默认」发送正常网页 Intent；固定应用则对当前网址重新查找所选包的可用组件，保留当前网址和匹配 MIME 后直接打开。组件变化可自动跟随；卸载、停用或启动失败时提示并恢复每次询问。
- 新偏好文件 `browser-preferences-v1` 仅保存模式和所选包名，忽略历史实验偏好。不记录网址、票据、MIME 或 Cookie；没有选择回调、启动器扫描、完整应用列表权限或全局设置修改。

## 历史真机记录

测试设备：OPPO Find X8 Ultra，ColorOS 16 / Android 16。

1. 通用浏览器能力查询漏掉已安装的 QQ 浏览器、夸克、百度；反复扫描不能解决，按品牌包名补丁不能作为通用方案。
2. local.19 包装网页 `ACTION_VIEW` 的 `ACTION_CHOOSER` 在该机没有弹出窗口，直接打开默认浏览器；回调识别到默认应用，不等于用户主动选中了它。
3. local.20 改成系统 `ACTION_PICK_ACTIVITY` 查询启动器应用，实际列出全部应用，用户明确认为不符合浏览器选择需求，要求移除。
4. 此前 JVM 回归只能验证应用发出的 Intent 和模拟结果，不能证明厂商系统的窗口、候选或最终浏览器符合预期。
5. browser-trial.22 用户真机截图确认系统面板可显示，但只有官方浏览器；「更多」和「编辑」也只有该候选。弹窗问题得到验证，候选完整性尚未解决。
6. browser-trial.23 用户反馈「完全可以了」，截图显示 16 个候选，包含 Edge、Chrome 及其他声明能处理网页的应用；用户要求移除诊断提示并加入默认选项。第 24 版据此继续实现默认设置，尚无该版真机反馈。

## 后续真机验证与发布检查

- 候选应来自系统声明的通用网页接收能力，显示名称和图标，不能把全部启动器应用当成浏览器列表；系统声明可能包含带网页能力的非浏览器应用。
- 用户选中某个浏览器后，传入的网址必须在该浏览器中打开；不能被系统默认浏览器重新接管，也不能只启动应用首页。
- 系统卡片的一次选择不自动成为默认；仅设置对话框明确选择并点击「保存」后才持久化，取消不打开、不保存。
- 可更换或清除本应用的选择。卸载、禁用、入口变化时提供明确反馈。
- 不自行更改系统全局默认浏览器，不申请读取全部应用的权限，不记录账号网址、认证票据或浏览器 Cookie。
- 发布前在上述 OPPO 真机及一种其他系统上验证三种默认模式、首次选择、重启保留、更换、取消和浏览器不可用等场景。当前第 24 版为用户明确要求的试验包入口。
- 自动测试覆盖行为约束，真机记录说明系统版本、实际候选和最终打开的浏览器；不能仅以测试数量证明功能已完成。
