# 可选后端与连接试验

默认 `transport: 'browser'` 无需此服务。以下代码用于继续研究小程序原生认证和教务查询，也可以在具备学校访问条件的环境中自行部署；部署成功不代表学校接口能够通过网络和页面跳转校验。

## 连接方式

| `transport` | 请求路径 | 配置 |
| --- | --- | --- |
| `browser`（默认） | Safari 查询后由本人复制、确认导入，本地展示 | 无后端 |
| `direct` | 小程序直接请求学校 | 微信合法域名与学校可访问网络 |
| `hybrid` | 自建云端处理 CAS，手机请求教务 | `cloudEnv`、`cloudService`，另需手机校园网与合法域名 |
| `cloudrun` | 可信微信云托管入口代理认证和查询 | `cloudEnv`、`cloudService`，服务器需可访问学校 |
| `http` | 小程序请求自建 HTTPS 后端 | `apiBase`，服务端微信 AppID / AppSecret |

学校 CAS 在微信内可能返回网页授权页；教务校验页面来源可能返回 `#E2140100001`。服务器也可能无法访问校内接口。当前没有已验证可用的云端 VPN 自动接入实现；请勿仅凭 `/health` 正常就认定教务已连通。手机浏览器模式不依赖这些试验连接。

## 本地启动（用于开发）

1. 安装 Python 3.10+，在本目录的上一级 `wechat/` 执行 `python -m pip install -r server/requirements.txt`。
2. 将 `server/.env.example` 复制为 `server/.env`，填写自己的配置。
3. 用 `python -c "import secrets; print(secrets.token_hex(32))"` 生成 `SUPERJLU_MASTER_KEY`；不要把输出或 `.env` 提交到仓库。
4. 普通 HTTPS 模式填写后端 `WECHAT_APP_ID`、`WECHAT_APP_SECRET`；前端只填写自己的 AppID 与 `apiBase`。
5. 运行 `python server/app.py`。默认监听 `127.0.0.1:8787`，`/health` 为健康检查。

开发者工具可把 `apiBase` 配为 `http://127.0.0.1:8787` 且 `transport: 'http'` 联调；手机必须使用配置合法域名的 HTTPS 服务，不能访问电脑回环地址。开发身份开关 `SUPERJLU_ALLOW_DEV_LOGIN` 默认为 `0`，对外部署保持关闭。

## 容器

在 `wechat/` 下执行 `docker build -t superjlu-wechat .`。容器使用非 root 用户，监听 8080；通过平台的环境变量或秘密管理填写主密钥与对应连接方式配置，不把 `.env` 打进镜像。文件存储目录为 `/app/.data`，重建容器后的持久性取决于部署环境，按需挂载专用存储。

该实现用于单实例：学校流程、微信令牌及同步任务保存在进程内存中，多实例不共享状态。重启会使内存认证会话失效；不要直接启用多副本并假定登录状态共享。`SUPERJLU_STARTUP_NETWORK_CHECK=1` 可启用启动时匿名网络诊断，镜像默认关闭此探测。

微信云托管身份模式仅接受由平台验证并注入的微信身份头，并核对平台环境变量 `CBR_ENV_ID`。不要在公网反向代理上把外部客户端自带的身份头当成已验证身份；普通自建服务使用 `/api/wechat/login` 的服务端微信 code 换取身份流程。

## 数据处理

启用后端后，用户同意的学校凭据会经过自己配置的服务，再提交给学校。密码和验证码不落盘，学校持久会话和缓存使用主密钥派生的每用户密钥及 AES-GCM 加密；主密钥丢失会导致已有缓存无法解密。组合连接使用短期内存 CAS 会话，业务查询在手机完成。前端业务缓存未额外加密。

只有手机浏览器导入方案获得过真实课表展示反馈；可选后端的自动化测试使用合成身份和模拟学校响应，不代表在任意服务器上均能登录教务。后端维护者应实际验证网络、微信身份来源、数据持久化和清除功能，再决定是否启用。
